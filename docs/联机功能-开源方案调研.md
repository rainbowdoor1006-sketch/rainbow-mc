# RAINBOW MC 联机功能 · 开源方案调研

> 调研日期：2026-10-23
> 结论先行：**首选「内置陶瓦联机（Terracotta）」**——它是目前中文启动器生态里唯一同时满足「开源、有 launcher API、许可证允许闭源启动器内置」的方案，HMCL、PCL-CE、FCL、ZL2、FMCL、MoLaunch、SJMCL、Axolotl 都已经接入。

---

## 一、先把「联机」拆开看

Minecraft 联机本质是三件事，任何方案都要解决：

1. **NAT 穿透**：房主在自家路由器后面，没有公网 IP，别人连不进来
2. **发现与连接**：房客怎么拿到房主地址（邀请码 / 域名 / 虚拟 IP / 局域网广播）
3. **会话管理**：房间生命周期、成员列表、端口映射、断线重连

按解决方式分成 6 类思路（下面逐条给开源项目）。

---

## 二、方案 A：内置陶瓦联机（Terracotta，基于 EasyTier）

**代表项目**：[burningtnt/Terracotta](https://github.com/burningtnt/Terracotta) ★231 · Rust · AGPL-3.0 + 内置例外条款 · 2026-10 仍在更新

**原理**

```
启动器下载 terracotta.exe  → 以 --hmcl <文件> 启动（集成模式）
→ 进程把 HTTP 端口写进文件
→ 启动器轮询 GET /state 拿房间状态
→ 房主点「创建房间」得到邀请码 U/XXXX-XXXX-XXXX-XXXX
→ 房客输邀请码加入 → 双方进入同一 EasyTier 虚拟网络
→ 陶瓦在内网里跑「脚手架」TCP 服务，把 MC 端口透给房客
→ 游戏里多人列表出现「陶瓦联机大厅」，双击即进
```

**关键技术事实**（从仓库文档核实）

- 底层 EasyTier 版本 `v2.5.0-terracotta.2`（自定义分支）
- 邀请码 = 34 进制编码，内含 `network_name` + `network_secret`，`U/` 前缀，16 字符每 4 位分隔
- HTTP API 只监听 `127.0.0.1`，端口随机，通过 `--hmcl <file>` 写文件或 `%TEMP%\terracotta\terracotta.lock`（2 字节大端端口）发现
- API：`GET /meta`、`GET /state`（waiting / host-scanning / host-starting / host-ok / guest-connecting / guest-starting / guest-ok / exception，`index` 单调递增，需按 index 去重轮询）
- 公共节点由 zkitefly 提供（`etnode.zkitefly.eu.org`），可换自建节点
- 本地还提供一个 Yggdrasil 认证端口（`yggdrasil_port`），房客以离线身份接入，不会因为正版验证被踢

**优点**

- 房间码联机，零配置，不需要公网服务器、不需要注册账号
- **官方给启动器留了 HTTP API**，`/state` 状态机直接能映射成 UI
- 许可证带例外条款：**只要打包未修改的二进制、或通过 IPC 调用并在界面标注版权，就不会传染 AGPL**（这正是为闭源启动器准备的）
- 已有 8 个启动器接入，踩坑成本低；问题也能参照它们的实现

**缺点**

- 多一个二进制（几 MB），启动器要负责下载、校验、升级、被杀软误报的处理
- 房主必须先「对局域网开放」（陶瓦会自动扫描本机 MC 端口）
- AGPL 例外条款要求**界面明显处标注 Terracotta 版权**，这条必须做
- 依赖它自己的公共节点做 P2P 引导，节点挂了会影响建连（可自建节点兜底）

**接入工作量**：小（1~3 天）。核心是进程管理 + 状态机 UI。

## 三、方案 B：自己集成 EasyTier（不用陶瓦）

**代表项目**：[EasyTier/EasyTier](https://github.com/EasyTier/EasyTier) ★14266 · Rust · LGPL-3.0

**原理**：启动器直接管 `easytier-core` + `easytier-cli`，自己实现「房间」概念：

```
房主：easytier-core --network-name <随机> --network-secret <随机> --ipv4 10.144.0.1
房客：easytier-core --network-name <同上> --network-secret <同上> --ipv4 10.144.0.2
→ 房客在游戏里直连 10.144.0.1:25565
```

**优点**

- 完全自主，不依赖第三方房间协议
- EasyTier 支持 P2P、NAT 穿透、KCP/QUIC、子网代理、公共节点中继
- LGPL 只要求「动态使用」，独立进程调用通常合规

**缺点**

- 邀请码、房间生命周期、端口扫描、成员列表、大厅 UI **全部要自己写**
- 局域网广播（`224.0.2.60:4445`）在虚拟网卡上不一定通，客户端可能看不到世界，只能手动填 IP
- 出问题要自己排查 NAT 类型（对称型 NAT 需要中继）
- 工作量：中（1~2 周）

## 四、方案 C：模组方案（e4mc / World Host）

**代表项目**

| 项目 | 语言 | 许可证 | 说明 |
|---|---|---|---|
| [vgskye/e4mc-minecraft-architectury](https://github.com/vgskye/e4mc-minecraft-architectury) ★300 | Java | MIT | 点「对局域网开放」自动生成公网域名，走 e4mc 官方中继 |
| [Gaming32/world-host](https://github.com/Gaming32/world-host) ★88 | Java | MIT | 同类，走 World Host 中继，房客即使没装 mod 也能进 |

**原理**

```
启动器给实例自动装 e4mc mod
→ 玩家进存档点「对局域网开放」
→ mod 向中继服务器申请子域名（如 xxx.e4mc.link）
→ 把域名发给朋友，朋友直接在多人游戏里添加服务器
```

**优点**

- **不需要我们出服务器/带宽**（用别人的公共中继）
- 操作最贴近原版：就是「对局域网开放」
- 代码开源（MIT），可以自己搭中继

**缺点**

- 需要版本/加载器匹配的 mod（1.20.1 Forge 有，但不是所有版本都有）
- 依赖第三方中继的可用性和限速（高峰期慢、可能被墙）
- 玩家得知道「用域名加服务器」，不如房间码直观
- 无法接管「房客没装 mod」的情况（e4mc 需要双方都装；World Host 部分版本可免）

**接入工作量**：小（半天），但体验不如房间码。

## 五、方案 D：自建中继隧道（frp / OpenP2P）

**代表项目**

| 项目 | 语言 | 许可证 | 说明 |
|---|---|---|---|
| [fatedier/frp](https://github.com/fatedier/frp) ★110102 | Go | Apache-2.0 | 老牌内网穿透，TCP/UDP 都支持 |
| [openp2p-cn/openp2p](https://github.com/openp2p-cn/openp2p) ★2041 | Go | MIT | P2P 优先，打不通才走中继 |
| [ntop/n2n](https://github.com/ntop/n2n) ★7045 | C | GPL-3.0 | 二层 VPN，支持广播（局域网发现可用） |

**原理**：房主跑 frpc 把 25565 映射到我们服务器的端口，房客连「服务器IP:端口」。

**优点**

- 完全自控，链路稳定可控
- 能顺便做「开服托管」这类增值功能

**缺点**

- **必须自己有公网服务器 + 带宽**：一个玩家 50~100 KB/s，10 人同时在线约 5 Mbps 起步
- 成本随用户线性增长，你做免费启动器很难扛
- 需要一套分配端口/回收的调度服务

**接入工作量**：中（1 周 + 持续服务器成本）。

## 六、方案 E：反向代理 + 域名路由（mc-router）

**代表项目**：[itzg/mc-router](https://github.com/itzg/mc-router) ★969 · Go · MIT

**原理**：所有房间共用 25565 端口，靠客户端 handshake 里的 hostname 区分房间（`room1.rainbow.icu:25565`）。

**优点**：一个端口服务无限房间，配合方案 D 做规模化很省端口。

**缺点**：玩家必须改「服务器地址」为域名；需要 DNS 泛解析；仍要中继带宽。

## 七、方案 F：纯 VPN 方案（ZeroTier / Tailscale）

| 项目 | 许可证 | 说明 |
|---|---|---|
| [tailscale/tailscale](https://github.com/tailscale/tailscale) ★38011 | BSD-3-Clause | WireGuard 组网，需登录账号 |
| [zerotier/ZeroTierOne](https://github.com/zerotier/ZeroTierOne) ★17209 | BSL | 需注册 network id |

**优点**：成熟稳定，穿透强。

**缺点**：要求玩家**注册账号 + 装客户端 + 加入同一个网络**，对 15 岁玩家群体门槛太高；BSL/账号体系也不适合我们直接内置。**不推荐**。

---

## 八、方案 G：UPnP / 手动端口映射引导

最原始做法：启动器调用 UPnP 给路由器打洞，把 `公网IP:端口` 给朋友。

**优点**：零成本、零依赖。

**缺点**：国内大部分路由器/运营商（CGNAT）根本打不通，成功率不到三成。**只能做兜底提示，不能当主功能**。

## 十、给 RAINBOW MC 的落地建议

**主方案：A（内置陶瓦联机）**，理由：

1. 你项目的定位就是「让不会折腾的人能玩」，房间码是门槛最低的形式
2. 它是**唯一明确允许闭源启动器内置**的方案（AGPL 例外条款）
3. HMCL 等 8 个启动器已经验证过这条路，出问题有参照
4. 我们不需要出带宽，成本可控

**我建议的具体实现（Electron 侧）**

```
① 首次点「联机」时下载 terracotta.exe 到 data/tools/terracotta/
   （按 /meta 校验版本，支持手动更新；下载源走我们自己的服务器做镜像，避免 GitHub 被墙）
② 用 --hmcl <临时文件> 启动，读端口
③ 500ms 轮询 /state，把状态映射到界面：
     waiting        → 「创建房间」
     host-scanning  → 「正在等待你进入存档并开放局域网」
     host-ok        → 显示邀请码 + 复制按钮 + 成员列表
     guest-*        → 「正在加入…」
     exception      → 显示错误原因
④ 界面上必须标注「联机能力由 Terracotta | 陶瓦联机 提供」（许可证要求）
⑤ 房主流程引导：进存档 → Esc → 对局域网开放 → 回启动器看邀请码
```

**兜底方案：C（e4mc）**——某些整合包/版本陶瓦扫描不到时，提供「一键安装 e4mc mod」备用入口。

**暂不做：D/E**（带宽成本不可控）、**F**（门槛太高）、**G**（成功率太低，只做提示文案）。

## 十一、风险与合规清单

| 风险 | 处理 |
|---|---|
| AGPL 例外要求 | 界面明显处标注 Terracotta 版权 + 不改它的二进制 |
| 杀软误报（未签名 exe） | 下载后校验哈希；申请代码签名证书（之前已调研过） |
| 公共节点不可用 | 支持自建 EasyTier 公共节点，配置项可填 |
| 玩家正版/离线混杂 | 陶瓦自带本地 Yggdrasil 端口，房客可离线接入 |
| 房间码泄露 | 邀请码只在房主界面展示，不做公开房间列表 |
| 国内下载 GitHub 失败 | 二进制放我们自己的服务器做镜像 |
